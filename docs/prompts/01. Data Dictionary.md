# 📗 Prompt 01 — Generar Data Dictionary (Qwen Code Terminal)

## Instrucciones de Ejecución

Este prompt está diseñado para ser ejecutado por **Qwen Code** desde la terminal. El operador debe decir:

> "Ejecuta el prompt 01 para generar el Data Dictionary"

Qwen Code debe seguir las instrucciones abaixo y generar el documento automáticamente.

---

## Tarea para Qwen Code

### ⚠️ RESTRICCIÓN CRÍTICA: REGENERACIÓN COMPLETA (NO EDICIÓN)

**ESTE PROMPT REQUIERE REGENERAR EL DOCUMENTO COMPLETAMENTE DESDE CERO.**

- **NO leas el archivo existente** para copiar o preservar contenido.
- **NO asumas que una sección "ya está bien"** porque existe en el archivo actual.
- **NO hagas edición mínima** (solo cambiar fechas o números).
- **SÍ genera TODO el contenido desde cero** siguiendo exactamente el template definido abajo.
- **SÍ reemplaza CADA sección** con contenido fresco analizado de los scripts ETL, aunque ya exista.
- **SÍ lee TODOS los scripts** para generar cada sección nueva.

> **Analogía:** No estás "editando" un documento. Estás "compilando" uno nuevo desde las fuentes. El archivo anterior es solo un placeholder que será sobrescrito por completo.

Analiza TODOS los scripts de `etl_pipeline/` y genera un diccionario de datos completo en `docs/03-ai-generated-content/02_data_dictionary.md`.

### Pasos de Ejecución

1. **Lee TODOS los scripts ETL:**
   - `01_generate_synthetic_data.py`
   - `02_setup_raw_layer.py`
   - `03_ingest_data.py`
   - `04_setup_business_core.py`
   - `m05_fuerza_laboral.py`

2. **Extrae de cada script:**
   - Qué tablas/vistas crea
   - Qué columnas tienen (lee el SQL o la lógica de generación)
   - Qué reglas de negocio aplica (fórmulas, condiciones, joins)
   - Qué funciones RPC define

3. **Para la capa RAW:**
   - Lee `02_setup_raw_layer.py` → documenta cada tabla creada
   - Genera tabla Markdown con: Columna, Tipo, Descripción, ¿Calculada o Fuente?

4. **Para la capa BUSINESS CORE:**
   - Lee `04_setup_business_core.py` → documenta la vista maestra y filtros
   - Explica reglas de negocio: `tenure_months`, `is_active_at_snapshot`
   - Marca columnas calculadas con `(C)` y fuente con `(F)`

5. **Para los DATA MARTS:**
   - Lee `m05_fuerza_laboral.py` → documenta cada MV y vista
   - Para cada una: qué métricas calcula, qué gráfico/frontend consume

6. **Funciones RPC:**
   - Extrae TODAS las funciones RPC del script m05
   - Documenta: parámetros, tipo de retorno, descripción, componente que la consume

7. **Reglas de simulación:**
   - Lee `01_generate_synthetic_data.py` → resume lógicas de negocio:
     - IPC por mes/país
     - Rotación natural y su aplicación
     - Coordenadas geográficas
     - Cualquier otra regla detectada

8. **Diagrama de linaje:**
   - Genera un diagrama Mermaid que muestre: CSV → Raw → Business → Data Marts → RPC

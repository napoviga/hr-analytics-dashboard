Auditoría Avanzada de Calidad, Hardcoding y Dependencias Fantasma (QA & Tech Lead Scan)

Actúa como un Senior QA Engineer, Tech Lead y Experto en DevSecOps. Necesito que realices una auditoría profunda y exhaustiva de todo este proyecto, cruzando la realidad del código fuente con nuestra documentación oficial (Blueprint).

Tu objetivo NO es crear nuevas funcionalidades, sino entregar un "Reporte de Auditoría" estricto en formato Markdown que detecte deuda técnica, código quemado (hardcoding), dependencias fantasma y vulnerabilidades.

Por favor, lee primero los documentos en `docs/03-ai-context/01_project_blueprint.md` y `docs/01-product-specs/01_navigation_sitemap.md` para entender la arquitectura esperada, y luego evalúa estos 6 pilares:

1. Prevención de Hardcoding (El Anti-Patrón Principal):

- Revisa meticulosamente los componentes visuales (especialmente `Demographics.jsx` o cualquier archivo que use `echarts-for-react`).
- Detecta si hay arreglos estáticos (ej. `['IT', 'Sales']` o `['Ene', 'Feb']`) quemados en los ejes (xAxis/yAxis), series, o menús desplegables. Todo dato categorizado debe construirse dinámicamente extrayendo los valores únicos de la respuesta JSON de Supabase.
- Detecta si hay URLs completas hardcodeadas en lugar de usar variables de entorno.

2. Dependencias Fantasma y Código Zombie:

- Package.json vs Realidad: Enumera las librerías instaladas en el frontend que no se importan en NINGÚN archivo `.jsx` o `.js` (Dependencias fantasma).
- Python Imports: Busca módulos en los scripts ETL (`import os, pandas, etc.`) que jamás se utilizan en el cuerpo del script.
- Código Zombie: Identifica variables, estados (`useState`), funciones o props declaradas dentro de los componentes de React que nunca se usan ni se renderizan.

3. Detección de Archivos Huérfanos y Basura:

- Identifica componentes de React que hayan quedado olvidados en la antigua carpeta plana `src/components/` o en `src/modules/` pero que no estén siendo importados por el ruteador o el layout.
- Busca scripts de Python antiguos (ej. `04_create_...` o `05_setup...`), archivos CSV de prueba, o archivos `.md` sueltos en la raíz que ya no formen parte de la nueva arquitectura.

4. Cruce de Blueprint vs. Realidad (Consistencia Arquitectónica):

- Compara los módulos declarados en `navigation.js` y el Sitemap con las carpetas físicas en `src/modules/`. ¿Hay carpetas huérfanas que no están en el menú? ¿Faltan carpetas?
- Verifica que el pipeline ETL respete el orden: Core Transversal (`04`) -> Data Marts Modulares (`m05`, `m06`).

5. Auditoría de Seguridad y Secrets:

- Escanea el código fuente buscando tokens o contraseñas hardcodeadas.
- Verifica que el archivo `.gitignore` proteja los `.env`, `__pycache__`, y `.venv`.
- Analiza las funciones RPC de PostgreSQL: ¿Los permisos `GRANT EXECUTE` están bien aplicados a `anon` o `authenticated`?

6. UI/UX y Buenas Prácticas de React (Linting):

- Busca componentes de React que usen estilos en línea (`style={{...}}`) en lugar de usar clases de Tailwind CSS.
- Detecta llamadas asíncronas a Supabase esparcidas desordenadamente dentro del `return` de los componentes visuales.

Entrégame el reporte estructurado, clasificando los hallazgos por nivel de severidad (🔴 Crítico [Ej: Hardcoding/Secrets], 🟡 Advertencia [Ej: Código Zombie], 🟢 Sugerencia). Si detectas errores críticos, proporciona el código exacto para solucionarlos o el comando para eliminar la basura.
